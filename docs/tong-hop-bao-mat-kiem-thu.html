2. Ba nhóm kiểm thử: tool là gì, làm gì, tác dụng

Ba "trụ" phủ 3 mặt: soi mã nguồn · soi thư viện · đánh app đang chạy.

Nhóm 1 — SAST (Static Application Security Testing)

MụcNội dung
Là gìSoi mã nguồn tĩnh — đọc code mà không chạy app, so với hàng nghìn mẫu lỗi.
ToolSemgrep (chạy qua Docker vì Windows)
Làm gìTìm pattern nguy hiểm: secret hardcode, input chưa lọc, dùng eval, crypto sai, thiếu kiểm quyền…
Tác dụngBắt lỗi ngay trong code của mình trước khi chạy — hợp nhất vì có full source TypeScript.
Phát hiện1 lỗi: GCM thiếu ép độ dài auth tag (crypto.service.ts) → đã vá.

Nhóm 2 — SCA (Software Composition Analysis)

MụcNội dung
Là gìSoi thư viện — đối chiếu dependency với CSDL lỗ hổng công khai (CVE).
Toolpnpm audit (có sẵn, không cần cài)
Làm gìĐọc lockfile → báo thư viện nào dính CVE, bản nào đã vá.
Tác dụngBắt lỗ hổng không phải do mình mà do thư viện (rủi ro chuỗi cung ứng).
Phát hiệnnext@16.3.4 dính CVE (cache poisoning) → nâng lên 16.3.8.

Nhóm 3 — DAST (Dynamic Application Security Testing)

MụcNội dung
Là gìĐánh app đang chạy (hộp đen) — gửi request thật, xem app phản ứng.
Tool 1 — OWASP ZAPTự động: bò khắp app + quét thụ động (header, cookie, CSP, XSS, lib lỗi). Nhanh, phủ rộng.
Tool 2 — Burp Suite CommunityThủ công: proxy chặn giữa trình duyệt và server, sửa & gửi lại request tùy ý (Repeater).
Tác dụngZAP bắt lỗi cấu hình phổ biến; Burp kiểm LOGIC máy không hiểu: IDOR, CSRF, step-up, phân quyền — mô phỏng đúng hacker.
Phát hiệnZAP: 0 FAIL, 57 PASS, 10 WARN (chủ yếu dev). Burp: CSRF 403 ✅, IDOR 400+403 ✅.

5. Hỏi — Đáp (thủ sẵn khi thầy hỏi)

Hỏi: Em test bảo mật bằng những phương pháp/công cụ gì?
Đáp: 3 nhóm — SAST (Semgrep) soi mã nguồn, SCA (pnpm audit) soi thư viện, DAST (OWASP ZAP tự động + Burp Suite thủ công) đánh app đang chạy. Ba nhóm phủ cả code, dependency và runtime.

Hỏi: SAST, DAST khác nhau chỗ nào?
Đáp: SAST đọc code tĩnh, không chạy app (hộp trắng); DAST tấn công app đang chạy (hộp đen). SAST bắt lỗi trong code mình viết, DAST bắt lỗi khi hệ thống vận hành thật.

Hỏi: Burp Suite là gì, tại sao cần?
Đáp: Là intercepting proxy ngồi giữa trình duyệt và server, cho em xem và sửa request trước khi gửi. Nhờ đó làm được điều giao diện không cho (gỡ CSRF token, tráo id) để test logic ở tầng server — nơi bảo mật thật sự nằm. ZAP tự động không hiểu được logic này.

Hỏi: Zero-knowledge nghĩa là gì?
Đáp: Mật khẩu được biến thành khóa ngay trong trình duyệt; server chỉ nhận bản băm để đăng nhập và ciphertext, không bao giờ thấy mật khẩu hay khóa giải mã. Vì vậy lộ DB cũng không đọc được dữ liệu.

Hỏi: Test tìm ra lỗi gì và xử lý ra sao?
Đáp: SAST tìm 1 lỗi crypto (AES-GCM thiếu ép độ dài auth tag) → vá bằng authTagLength:16 + kiểm độ dài tag. SCA tìm CVE của Next.js → nâng cấp. DAST xác nhận CSRF, IDOR, header đều hoạt động (0 lỗi nghiêm trọng).

Hỏi: Chống IDOR thế nào?
Đáp: Mọi thao tác credential đều lọc theo userId của phiên; id sai định dạng bị ParseUUIDPipe chặn (400), id của người khác bị chặn (403 "không thuộc về bạn"). Đã chứng minh bằng Burp.

Hỏi: Vì sao log IP ra ::1?
Đáp: Vì test ở local nên IP thật chính là localhost. Khi deploy sau proxy/CDN, đọc IP qua trust proxy/cf-connecting-ip sẽ ra IP client thật và không giả mạo được.

Hỏi: Penetration testing là gì, có làm không?
Đáp: Pentest là quy trình mô phỏng tấn công (quét → khai thác → báo cáo), không phải 1 công cụ. Em đã làm một đợt pentest quy mô nhỏ, dùng chính 3 nhóm tool trên, ánh xạ kết quả theo OWASP Top 10.
